# Bash and Codemode collapsed output implementation plan

1. Adapt the current uncommitted implementation to the agreed extension-wrapper approach. Reuse relevant rendering helpers and tests rather than discarding all the work. Preserve the committed Pi 1.0.0 dependency update and custom-tool partial-result blink fix. Do not commit, change release metadata, reset the extension, or touch unrelated working-tree changes.

2. Remove our production Codemode registration through `createCodemodeExtension()` and `registerPatchedTool()`. Remove Codemode from `BUILT_IN_PATCHES` and restore the corresponding core-tool registration expectations. Pi must continue loading and registering its own built-in Codemode extension. Do not disable that extension, edit user settings, suppress startup diagnostics, or defer registration to evade the replacement warning.

3. Use only the existing `ExtensionRunner.prototype.getAllRegisteredTools` hook for extension-tool rendering. With `patchCustomTools: true`, wrap eligible third-party extension tools and apply specialized rendering to native Codemode. With `patchCustomTools: false`, do not install or retain that hook; both categories render natively. Preserve the existing setting-driven installation, disposal, reload, and immediate-refresh lifecycle. Core Read/Bash/etc. enhancements remain independent of this switch. Add no second hook or always-installed interception layer.

4. Identify native Codemode using the registered definition's name and Pi's built-in source metadata: `name === "codemode"`, `sourceInfo.source === "builtin"`, and `sourceInfo.path === "builtin:codemode"`. A third-party replacement named `codemode` must keep ordinary custom-tool behavior. Preserve existing wrapper eligibility checks, already-wrapped markers, definition caching, and third-party `renderShell: "self"` ownership. Leave malformed registry entries unchanged and use the existing compatibility reporter.

5. Keep the dedicated entry point `src/tools/codemode.ts`, but make it create a rendering-only wrapper around the definition Pi supplied rather than register a tool. Preserve `execute`, parameters, schema identity, descriptions, prompt metadata, exposure, activation defaults, argument preparation, and loadout hooks by reference where applicable. Keep Codemode-specific lifecycle and result logic out of the generic definition adapter. Reuse existing state, shell, tree, and fallback helpers where they remove duplication; do not create a generic native-tool routing framework or construct an unused generic result wrapper.

6. Retain the `bashCollapsedDisplay` to `collapsedOutputDisplay` rename in the config interface, defaults, schema, getter, settings UI, render-refresh list, consumers, tests, and README. Keep `"preview" | "summary"`, with `"preview"` as the default. Use the UI label `Collapsed output`. Explain that it controls Bash and enhanced Codemode, and that Codemode follows it only while `patchCustomTools` is enabled. Add no migration or alias: ignore the obsolete key while preserving other valid settings.

7. Leave Bash behavior unchanged. Share only the small output-window selector, collapsed-line formatter, and duration formatter Codemode actually needs. Keep Bash execution timing and error parsing Bash-specific. Preserve existing Bash output contracts. Do not build a configurable rendering framework or copy the Bash module hierarchy.

8. Keep implementation ownership and style clear. `src/tools/codemode.ts` owns specialized renderer integration; narrowly scoped helpers under `src/tools/codemode/` handle calls, result interpretation, formatting, or timing where useful. Use existing semantic themes, width utilities, hyperlinks, and expansion helpers. Use visible tree symbols and neighboring naming conventions. Avoid unnecessary forwarding modules, duplicated wrappers, and unrelated shared-renderer refactors.

9. Render collapsed Codemode calls as one highlighted script-preview line using Pi's public JavaScript highlighter before ANSI-safe truncation. Preserve native expanded script rendering, including indentation, interior blank lines, and complete returned source. Apply the existing wrapped-tool capitalization preference, but do not extend that preference to core tools in this feature; uniform capitalization is a separate follow-up. Calculate hidden call content at the actual render width. Match Read/Bash by blinking during argument generation and live compact execution, using a static indicator while effectively expanded, and stopping on settlement. Preserve existing third-party indicator behavior; do not introduce a speculative activity fallback or another indicator setting.

10. Read nested-call information from the exported `CodemodeToolDetails` shape. Replace individual argument-heavy rows in collapsed mode with total call count and nonzero running, failed, and cancelled counts. Count native records, not a reconstructed recursive call graph. A caught nested failure must not label the script as failed; use Pi's result error state for overall failure.

11. Recognize Pi's exact first script-header text block to obtain final wall time and exclude that header from collapsed output. Preserve headerless validation errors and unfamiliar content. Do not strip similar words from ordinary output. Prefer Pi's separate script-error block over text printed before failure when choosing a diagnostic.

12. In `preview` mode, show up to three logical output lines. For longer output, show the first line, the existing `+N lines` omission row, and the last line. Truncate long lines to available width instead of wrapping them into unbounded previews. Keep interior blank lines and Bash's trailing-newline normalization. Omission counts refer to returned logical lines, not terminal rows or unavailable spilled content.

13. In `summary` mode, hide ordinary text output and report its line count. Keep one short script-failure diagnostic visible in either mode when the ordinary preview would hide it; do not duplicate an already-visible diagnostic. Use `(no output)` only for completed results without text or images. Running results show progress instead of claiming empty output.

14. Keep aggregate metadata at the bottom in this order where applicable: call counts and exceptional statuses, elapsed/final duration, available model-call cost, output/image counts, actual truncation status, and expansion hint. Omit irrelevant fields. Use existing semantic theme colors and separators. Let metadata wrap safely on narrow terminals rather than hiding failures or truncation notices.

15. Report costs only from data supplied to the renderer. Pi 1.0.0's TUI passes `content` and `details`, not aggregate result usage. Sum available native `details.calls[].cost` values and label the subtotal `model calls`; do not imply it includes unreported tool costs or sum nested-call durations. Preserve useful precision for small amounts. Retain native costs and native cost summaries in expanded mode, accepting the agreed duplication with our footer. Add no speculative aggregate-usage branch.

16. Keep live duration separate from blinking. Record an observed execution start only for a live call, never during argument generation or historical rendering. Reuse the adapter's authoritative activity callback for executing calls. Request redraw every 250 ms while a live partial result is displayed, with at most one timer per call. Stop and freeze timing on settlement, error, activity loss, or wrapper disposal; reuse existing tool-timer registration and shutdown cleanup. Prefer Pi's final reported wall time, falling back only to duration actually observed live. Do not invent historical durations or wrap native execution to measure time.

17. Delegate expanded result rendering to the original native renderer and append our metadata footer. Preserve native component reuse and invalidation, per-call arguments/errors/statuses/timing, interior blank lines, and all returned output. Do not cap expanded Codemode with `maxExpandedEntries`. Do not parse rendered native lines to remove duplicate cost summaries, and do not claim expansion recovers content Pi omitted.

18. Keep full-output links visible in both collapsed modes when `details.fullOutputPath` is supplied. Distinguish native truncation from local preview omission. Normalize only recognized native presentation envelopes; preserve failed-spill diagnostics and unfamiliar warnings. Label counts as returned lines when original output is unavailable. Do not automatically read spilled files or modify model-facing results.

19. Leave attachments and image rendering to Pi. The shared display setting controls text only. Show a concise image count so image-only results are not presented as empty, and test with images shown and hidden. Do not add an image renderer or alter image blocks.

20. Use `Component.render(width)` throughout, reserving prefix and padding space before truncation. Recompute expansion hints on resize and settings invalidation. Offer expansion only when it reveals hidden source, nested details, or output; a short summary diagnostic that already shows all output needs no hint. Respect the existing hint toggle and configured keybinding. Keep factory and deferred-layout fallbacks safe, bounded when collapsed, and complete when expanded. Reuse existing reporting rather than adding an error-handling framework. Retain the narrow-width guard only with focused regression coverage.

21. Replace obsolete replacement-registration tests with real registry-wrapper integration tests. Load Pi's actual built-in Codemode through its public factory in the test harness, with built-in loading enabled. Verify that its extension remains loaded, registration is not duplicated, no Codemode replacement warning is produced, and native execution, schema identity, loadout behavior, activation, allowlists/denylists, and reload remain unchanged. Test third-party same-name replacements, self-rendering ownership, wrapper cache reuse, settings toggles, disposal, and independence of core-tool rendering from `patchCustomTools`.

22. Test the renamed setting's persistence, validation, default, obsolete-key handling, unchanged menu size, and immediate refresh. Check that disabling `patchCustomTools` returns native Codemode definitions and re-enabling it restores specialized rendering through the existing lifecycle. Verify that disposal and toggles do not leak live-duration timers. Do not require users to change their built-in-extension settings.

23. Retain and adapt focused Codemode tests for preview/summary, short/long lines, blank lines, ANSI, wide characters, resize, missing/malformed metadata, many calls, partial progress, nested failures versus script failure, cancellation, cost precision, truncation, spill links/failures, images, component reuse, fallback rendering, and full native expansion. Include a few real local sandbox executions. Test argument-generation blinking, execution-only timing, one timer per call, frozen final durations, historical rendering, and cleanup with deterministic clocks. Make no paid model calls or real MCP connections.

24. Run the full extension suite, scoped TypeScript checks, formatting, `git diff --check`, and native Codemode/MCP rendering smoke checks. Exercise dark/light themes and regular/fullscreen rendering through real Pi components. Include startup checks with built-in Codemode enabled and both values of `patchCustomTools`, asserting no replacement warning from this extension. Report the unrelated SearXNG root type-check failure separately if it remains. Add no regular-mode viewport workaround, and distinguish automated checks from pending manual terminal/image review.

25. Update README and settings descriptions to explain extension-tool wrapping, Codemode's dependency on `patchCustomTools`, the shared output mode, diagnostics, execution-only live timing, model-call costs, spill links, and expanded native details. Remove the factory-registration and always-enhanced Codemode claims and the instruction to disable built-in Codemode. Keep documentation concise, avoid unrelated formatting churn, and leave versions, screenshots, and publishing assets alone.

26. Review every changed and new file before handoff, not just test results. Look for leftover Codemode registration, warning suppression, always-installed hooks, tool-specific branches in generic code, unnecessary abstractions, duplicate rendering, unsupported metadata, inconsistent settings descriptions, indicator regressions, timer leaks, weak integration tests, and unrelated edits. Fix findings, rerun affected checks, and report review findings and remaining limitations separately from validation results. Leave the implementation and this temporary plan uncommitted for user review.
